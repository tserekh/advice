# SochiGPT - RAG-based Telegram Bot

Ретрофиттинг вашего бота для ответов на вопросы с использованием RAG (Retrieval-Augmented Generation).

## Что изменилось

### Архитектура
- **Было**: Поиск похожих вопросов через FastText + возврат готовых ответов
- **Стало**: 
  1. Векторный поиск через sentence-transformers + ChromaDB
  2. Генерация ответов через локальную LLM (llama-cpp-python)
  3. Fallback режим только с retrieval при отсутствии LLM

### Ключевые улучшения
- ✅ Современные мультиязычные эмбеддинги (paraphrase-multilingual-MiniLM-L12-v2)
- ✅ Векторная база данных ChromaDB для быстрого поиска
- ✅ Локальная LLM через llama-cpp-python (оптимизировано для слабых серверов)
- ✅ Гибридный режим: LLM + RAG или только RAG
- ✅ Персистентное хранение векторов
- ✅ Контекстная генерация ответов на основе retrieved документов

## Установка

### 1. Установите зависимости

```bash
pip install -r requirements.txt
```

### 2. Скачайте модель LLM (опционально, но рекомендуется)

Для слабых серверов используйте квантованные модели:

```bash
mkdir -p models
cd models

# Вариант 1: Llama-2-7B-Chat (4-bit квантование, ~4GB)
wget https://huggingface.co/TheBloke/Llama-2-7B-Chat-GGUF/resolve/main/llama-2-7b-chat.Q4_K_M.gguf

# Вариант 2: Более легкая модель Mistral-7B (4-bit, ~4GB)
wget https://huggingface.co/TheBloke/Mistral-7B-Instruct-v0.2-GGUF/resolve/main/mistral-7b-instruct-v0.2.Q4_K_M.gguf

# Вариант 3: Минимальная модель Phi-2 (~2GB)
wget https://huggingface.co/TheBloke/phi-2-GGUF/resolve/main/phi-2.Q4_K_M.gguf
```

**Важно**: Если не скачаете модель, бот будет работать в режиме retrieval-only (без генерации).

### 3. Настройте конфигурацию

Отредактируйте `config.py` под ваш сервер:

```python
# Для очень слабых серверов уменьшите:
llm_n_ctx = 1024      # Размер контекста
llm_n_threads = 1     # Количество CPU потоков
llm_n_batch = 256     # Размер батча

# Выберите более легкую embedding модель если нужно:
embedding_model_name = "sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2"
```

## Использование

### Шаг 1: Подготовьте и проиндексируйте данные

```bash
python prepare.py
```

Это:
1. Обработает чаты из `data/ChatExport*/`
2. Создаст файл `data/question_reply.tsv`
3. Заиндексирует Q&A пары в векторную базу ChromaDB

### Шаг 2: Запустите бота

```bash
python app.py
```

Бот автоматически:
- Инициализирует RAG движок
- Загрузит LLM (если доступна)
- Начнёт обрабатывать сообщения

## Режимы работы

### 1. Полный RAG + LLM (рекомендуется)
- Поиск релевантных документов
- Генерация контекстного ответа через LLM
- Наилучшее качество ответов

### 2. Только Retrieval (fallback)
- Если LLM не загружена
- Возвращает лучший найденный ответ
- Показывает similarity score

## Настройка под слабый сервер

### Оптимизация памяти
```python
# В config.py уменьшите параметры:
llm_n_ctx = 1024      # вместо 2048
llm_n_threads = 1     # вместо 2
llm_n_batch = 256     # вместо 512
```

### Используйте меньшую модель
- Phi-2 (~2GB) вместо Llama-2-7B (~4GB)
- TinyLlama-1.1B (~1GB) для очень слабых серверов

### Отключите LLM полностью
Если сервер слишком слабый, просто не скачивайте модель. Бот будет работать в режиме retrieval-only.

## Как это работает

### Pipeline обработки запроса:

1. **Пользователь задаёт вопрос** → Telegram бот
2. **Retrieval** → Поиск топ-3 похожих Q&A в векторной базе
3. **Generation** (если LLM доступна):
   - Формирование промпта с контекстом
   - Генерация ответа через LLM
4. **Fallback** (если LLM недоступна):
   - Возврат лучшего найденного ответа
5. **Ответ пользователю**

### Пример промпта для LLM:
```
[Контекст 1]
Вопрос: Какой отель выбрать в Сочи?
Ответ: Рекомендуем отель "Жемчужина" у моря

[Контекст 2]
Вопрос: Где остановиться в Адлере?
Ответ: Отель "Олимпийский" рядом с стадионом

Вопрос пользователя: Посоветуйте отель в Сочи у моря

Используя приведённый выше контекст, дай точный и полезный ответ.
```

## Troubleshooting

### Ошибка: "Model not found"
- Скачайте модель в папку `models/` или отключите LLM

### Ошибка: "Vector store is empty"
- Запустите `python prepare.py` для индексирования данных

### Медленная работа
- Уменьшите `llm_n_ctx` и `llm_n_batch` в config.py
- Используйте меньшую модель
- Увеличьте `min_similarity_threshold` для меньшего количества retrievals

### Недостаточно памяти
- Используйте более квантованную модель (Q3_K_S вместо Q4_K_M)
- Уменьшите размер контекста
- Отключите LLM полностью
